# 01 — 專案章程 (Project Charter)

## 1. 願景

建立一個統一平台，使用者（與自動化腳本）只需要一套系統，就能開啟、檢視、編輯、轉換、批次處理
辦公文件、PDF、試算表、簡報、CSV 與 CAD 圖檔，不必在 Word / Excel / PowerPoint / Acrobat / AutoCAD 之間切換。

## 2. 目標

1. **統一開啟**：任何支援格式都能自動辨識並開啟，取得一致的文件模型（中繼資料、頁/工作表/投影片/圖層、文字、影像）。
2. **檢視**：每種格式都能在 Web 介面中渲染預覽。
3. **編輯**：涵蓋各原生軟體「日常最常用」的編輯功能（見第 5 節功能對照表）。
4. **轉換**：任意格式之間透過轉換圖 (conversion graph) 找到可行路徑。
5. **自動化**：CLI 與 REST API 讓所有功能可被腳本、批次流程呼叫（自動化工程友善）。
6. **可測試**：每項功能皆有自動化測試與測試報告。

## 3. 關於「包含原本軟體的所有功能」

Microsoft Office、Acrobat、AutoCAD 各自累積了數十年、數千項功能，**一次做到 100% 等同並不實際**。
本專案採用以下策略逐步逼近：

- 以「**功能對照表**」（第 5 節）列出每個原生軟體的功能，依優先級 P0 → P3 分批實作。
- P0/P1（開啟、檢視、常用編輯、轉換）優先完成，形成可用產品。
- P2/P3（進階/冷門功能）列入後續 Roadmap 持續擴充。
- 每次 Routine 執行時若發現遺漏的功能，可追加到 Roadmap 尾端（標註來源）。
- 對專有封閉格式（DWG、舊版 DOC/XLS/PPT）以「轉換為開放格式後處理」為策略。

## 4. 範圍

### 範圍內
- 第 5 節列出的格式與功能
- Python 函式庫 `anydoc`、CLI `anydoc`、FastAPI 服務、Web 前端
- 批次處理 / 管線 (pipeline) 定義
- 安全性：檔案大小限制、ZIP bomb 防護、巨集剝除、上傳隔離

### 範圍外（目前）
- 多人即時共同編輯（可列為未來工作）
- VBA 巨集「執行」（只做讀取/剝除）
- 3D CAD 實體建模（只處理 2D 圖面與 3D 實體的中繼資料）
